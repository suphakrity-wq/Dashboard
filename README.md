# ทำไมคนไทยถึงชอบเสพสื่อดราม่า แต่ไม่เสพข่าวโลก?

Dashboard แสดงผลสำรวจพฤติกรรมการเสพสื่อ — เว็บ static ไม่มี backend ดึงข้อมูลจาก Google Sheet โดยตรง

## คอลัมน์ที่ Dashboard คาดหวัง (แก้ได้ใน config.js)
| คอลัมน์ | ชนิด | ใช้ทำอะไร |
|---|---|---|
| ช่วงอายุ / เพศ / อาชีพ / แพลตฟอร์มหลัก | ข้อความ | ตัวกรอง + กราฟแยกกลุ่ม |
| ชั่วโมงต่อวัน | ตัวเลข | KPI เวลาเสพสื่อเฉลี่ย |
| ประเภทเนื้อหาที่เสพบ่อย | เลือกได้หลายข้อ คั่นด้วย `,` | กราฟแท่งนอน (ตั้ง `multi: true`) |
| ความสนใจข่าวดราม่า / ความสนใจข่าวโลก | 1–5 | KPI + เปรียบเทียบรายช่วงอายุ |
| เหตุผลที่ไม่ตามข่าวโลก | ข้อความ | กราฟแท่งนอน |

ถ้าใช้ Google Form → ชื่อคอลัมน์คือ "ข้อความคำถาม" ทั้งประโยค เอามาใส่ `column` ตรง ๆ ได้เลย

## ฟอนต์
ใช้ **DB Heavent** จากโฟลเดอร์ `fonts/` แปลงเป็น `.woff2` ไว้ที่ `assets/fonts/` แล้ว (เล็กกว่า .ttf ~4 เท่า โหลดเร็วกว่ามาก)
ถ้าเปลี่ยนไฟล์ฟอนต์ใหม่ แปลงด้วย:
```bash
pip3 install fonttools brotli
python3 -c "from fontTools.ttLib import TTFont; f=TTFont('fonts/ชื่อไฟล์.ttf'); f.flavor='woff2'; f.save('assets/fonts/ชื่อใหม่.woff2')"
```
แล้วเพิ่ม `@font-face` ที่หัวไฟล์ `assets/css/style.css`
หมายเหตุ: DB Heavent เป็นฟอนต์ลิขสิทธิ์ ถ้าเผยแพร่เว็บสาธารณะควรตรวจสิทธิ์การใช้งานบนเว็บก่อน

## โครงหน้า — เว็บหลายหน้า (แถบซ้าย)
| หน้า | เนื้อหา |
|---|---|
| **สรุปผล** `#/summary` | คำตอบของคำถามวิจัย + สาเหตุหลัก + สิ่งที่ดึงคนไปหาดราม่า |
| **ช่องว่างการรับรู้** `#/gap` | เทียบข่าวโลก vs ดราม่า + ข่าวรายชิ้นครบทุกข่าว |
| **เหตุผลเบื้องหลัง** `#/reasons` | ทำไมเลือก/ไม่เลือก ทั้งสองฝั่ง + สาเหตุ 6 อันดับพร้อมทางแก้ |
| **พฤติกรรมการเข้าถึง** `#/behavior` | เจอข่าวยังไง ช่องทาง ตัวตัดสินใจ ประเภทข่าว |
| **ข้อมูลดิบ** `#/data` | ตารางทุกคอลัมน์ · คลิกแถวเพื่อกางคำตอบเต็มรายคน (คำตอบหลายข้อแสดงเป็นชิป) |

ทุกหน้ามี **แถบสรุป 4 ตัวเลขด้านบน** และแท็บ+ตัวกรองใช้ร่วมกันทุกหน้า (กรองแล้วค้างข้ามหน้า)
URL เป็น hash จึงแชร์ลิงก์เฉพาะหน้าได้ และใช้กับ GitHub Pages ได้เลย

## เพิ่ม/แก้หน้า
แก้ `pages: []` ใน `config.js` — หนึ่งหน้าประกอบด้วย `summary` (แถบตัวเลขบน) และ `blocks`
บล็อกที่ใช้ได้: `verdict` (การ์ดคำตอบ) · `causes` (สาเหตุ+ทางแก้) · `pull` (แรงดึงฝั่งดราม่า) · `charts` (กลุ่มกราฟ) · `notes` (บทความ) · `table` (ตารางดิบ)
ไอคอนใช้ชื่อจาก [Material Symbols](https://fonts.google.com/icons) ใส่เป็น `icon: "psychology"` ได้เลย

## การใช้เอกสารงานวิจัย (โฟลเดอร์ เอกสาร/)
เอกสารถูกใช้ 3 ทาง ทั้งหมดรวมอยู่ในหน้า **ข้อสรุป & ข้อเสนอ** (`#/conclusion`)

**1. ค่าอ้างอิงเชิงตัวเลข** — `core/benchmarks.js` เทียบตัวเลขของกลุ่มตัวอย่างกับผลสำรวจระดับประเทศ
| ค่าอ้างอิง | ตัวเลข | ที่มา |
|---|---|---|
| คนไทย 18–34 ใช้โซเชียลเป็นแหล่งข่าวหลัก | 63% | Reuters DNR 2025 (น.156) |
| ใช้ TikTok ดูข่าว | 49% (+10 จุด) | Reuters DNR 2025 (น.157) |
| ใช้ Facebook ดูข่าว | 62% | Reuters DNR 2025 (น.157) |

**2. ข้อเท็จจริงประกอบ** — 8 ข้อจาก Reuters / ETDA / Robertson / Prior / CLT / Kim & Zhou / Yaros
เช่น *"คนไทยใช้อินเทอร์เน็ตเฉลี่ย 8 ชม. 57 นาที/วัน"* (ETDA 2565) และ *"ทุกคำเชิงลบในพาดหัวเพิ่มคลิก 2.3%"* (Robertson 2023, Nature)

**3. ผูกกับข้อเสนอแนะ** — ทุกวิธีแก้ในหน้าเว็บมีบรรทัดอ้างอิงว่ามาจากงานวิจัยชิ้นไหน

> ตัวเลขทุกตัวใน `benchmarks.js` คัดจากเอกสารจริงพร้อมเลขหน้า ไม่มีการประมาณเอง
> ถ้าเพิ่มเอกสารใหม่ ให้เพิ่มใน `SOURCES` และ `BENCHMARKS`/`CONTEXT_FACTS` ที่ไฟล์เดียว

## ระบบประเมินคำตอบปลายเปิด
`core/textAnalysis.js` — จัดหมวดข้อความที่ผู้ตอบเขียนเอง (ข้อ 5) ด้วยกฎคำสำคัญ ไม่ใช้ AI จึงตรวจสอบและแก้ได้เอง
- **11 ธีม** แยกเป็น *แรงดึง* (ทำให้หยุดดู) กับ *อุปสรรค* (ทำให้เลื่อนผ่าน) แต่ละธีมมีวิธีแก้ + งานวิจัยที่รองรับ
- แสดง **ข้อความจริงของผู้ตอบ** เป็นตัวอย่างประกอบทุกธีม (ยกมาอ้างอิงได้)
- บอก **% ที่จัดหมวดได้** และเปิดดูคำตอบที่ยังจัดไม่ได้ เพื่อเอาไปเพิ่มคำสำคัญ
- กันปัญหาคำไทยซ้อนคำ เช่น "อยากรู้" ไม่ถูกจับเป็น "ยาก" (ดู `MASK` ในไฟล์)

## วิธีคำนวณคำตอบ (สถิติ)
เลิกใช้เกณฑ์ "ต่างกันเกิน 10%" ที่ตั้งเอง เปลี่ยนมาใช้การทดสอบทางสถิติ — โค้ดอยู่ที่ `core/stats.js` (ฟังก์ชันบริสุทธิ์ ทดสอบแยกได้)

| วิธี | ใช้ตอนไหน | ผลที่แสดง |
|---|---|---|
| **Paired t-test** | ตัดสินคำถามวิจัยหลัก | ผลต่างเฉลี่ย + ช่วงเชื่อมั่น 95% + t, df, p |
| **Wilcoxon signed-rank** | ตรวจซ้ำโดยไม่สมมติการแจกแจงปกติ | ค่า p อีกชุด ถ้าตรงกันแปลว่าข้อสรุปมั่นคง |
| **Cohen's dz** | บอกว่าต่าง "มากแค่ไหน" ไม่ใช่แค่ "ต่างไหม" | เล็กมาก/เล็ก/ปานกลาง/ใหญ่ |
| **Wilson score interval** | ช่วงเชื่อมั่นของทุกตัวเลข % | "55% · ช่วงเชื่อมั่น 95% 40–69%" |
| **Welch's t-test** | เทียบช่องว่างระหว่างกลุ่มพฤติกรรม | ต่างกันจริงไหม พร้อมค่า p |
| **Power analysis** | เมื่อผลยังไม่มีนัยสำคัญ | บอกว่าควรเก็บเพิ่มกี่คน (อำนาจ 80%) |

**ทำไมต้องเป็น paired:** ผู้ตอบ 1 คนให้ค่า 2 ค่า (รู้จักข่าวโลกกี่ข่าว / ข่าวดราม่ากี่ข่าว) จึงต้องทดสอบผลต่างรายคน ไม่ใช่เทียบค่าเฉลี่ยสองกลุ่มแยกกัน — ถ้าใช้ผิดประเภทจะได้ค่า p ที่หลวมเกินจริง

**ตรวจความถูกต้องของสูตรแล้ว** เทียบกับค่าจากตาราง t มาตรฐาน:
`t=2.086, df=20 → p=0.0500` · `t=2.262, df=9 → p=0.0500` · `t=1.0, df=10 → p=0.3409` · `tCritical(df=24)=2.064` · `Wilson 15/25 = 40.7–77.0%` — ตรงทุกตัว

**ผลกับชุดข้อมูลทดสอบทั้ง 9 ชุด**
```
realistic  จริง        Δ=+4.7 CI[3.8,5.5]  p<.001  dz=2.28 (ใหญ่)
world      ไม่จริง      Δ=-2.6 CI[-3.3,-1.9] p<.001  dz=-1.44 (ใหญ่)
tie        ยังไม่ต่าง   Δ=-0.1 CI[-0.9,0.7]  p=.853  dz=-0.03 (เล็กมาก)
tiny (3 คน) ยังสรุปไม่ได้ — n < 5 ไม่ทดสอบ
```
ช่วงความเชื่อมั่นของชุด `tie` คร่อมเลข 0 ซึ่งเป็นสัญญาณที่ถูกต้องว่ายังสรุปทิศทางไม่ได้

## หลักการสื่อสารที่ยึดในหน้าเว็บ
1. **ทุกหน้าบอกว่าตัวเองตอบคำถามอะไร** — บรรทัด "หน้านี้ตอบว่า…" ใต้หัวเรื่อง เขียนเป็นภาษาคน ไม่ใช่ชื่อหัวข้อ
2. **ทุก % มีจำนวนคนกำกับ** — "60% · จากผู้ตอบ 25 คน" และในรายการอันดับเขียน "28% ของ 25 คน" เพื่อไม่ให้ % หลอกตาเมื่อฐานน้อย
3. **ไม่ใช้ศัพท์ภายใน** — เลิกเรียก "ข่าวชุด A / ชุด B" ในทุกจุดที่ผู้ใช้เห็น ใช้ "ข่าวโลก / ข่าวดราม่า" อย่างเดียว
4. **ตัดสิ่งที่ตีความยากออก** — เอา gauge ออกจากหน้าสรุป เพราะเลข "173%" ต้องแปลในหัวก่อน ขณะที่ "ต่างกัน 3.1 ข่าว" ที่อยู่ข้าง ๆ เข้าใจได้ทันที
5. **กราฟทุกตัวมีประโยคสรุปนำ** — บอกก่อนว่ากราฟนี้แปลว่าอะไร แล้วค่อยให้ดูตัวเลข
6. **กลุ่มเล็กต้องเตือน** — กลุ่มที่มีน้อยกว่า 3 คนจะจางลงพร้อมข้อความ "ตัวเลขยังแกว่งง่าย"

## บล็อกเทียบกลุ่ม (`compare`) — ส่วนที่ตอบคำว่า "ทำไม"
เดิม dashboard บอกได้แค่ "อะไรเยอะ" แต่ไม่เคยบอกว่า "อะไรสัมพันธ์กับอะไร"
บล็อกนี้เทียบ **ช่องว่างข่าวโลก/ข่าวดราม่า ระหว่างคนที่มีพฤติกรรมต่างกัน** เช่น
- เจอข่าวโดยบังเอิญ vs ตั้งใจหาข่าวเอง
- คนใช้ TikTok / Facebook / YouTube / เว็บข่าวโดยตรง

พร้อมประโยคสรุปอัตโนมัติว่า *"กลุ่มที่ช่องว่างกว้างที่สุดคือ… แคบที่สุดคือ…"*
เพิ่มกลุ่มใหม่ได้ในไฟล์ `pages/behavior.js` โดยใส่ `groups: [{label, match}]`

## หน้า "ข้อสรุป & ข้อเสนอ" ตอบ 3 คำถาม
1. **สาเหตุหลักคืออะไร** — จับคู่คำตอบแบบเลือกตอบกับคำตอบปลายเปิด (ถ้าสองแหล่งไม่ตรงกัน จะไม่เขียนว่า "สอดคล้อง")
2. **ทำไมถึงเป็นแบบนั้น** — หลักฐาน 3 ชั้น: ข้อมูลเรา + เสียงจากผู้ตอบ + งานวิจัยภายนอก
3. **ควรแก้ยังไง ใช้วิธีอะไร** — เรียงวิธีตามสัดส่วนคนที่ติดปัญหานั้น พร้อมบอกว่าแก้ที่สาเหตุข้อไหนและอ้างอิงจากไหน

## เมื่อกลุ่มตัวอย่างแคบ (กรณีของงานนี้)
ผู้ตอบจริงอาจอยู่ช่วงอายุเดียวกันเกือบทั้งหมด ระบบจึงปรับตัวเองดังนี้
- **เลือกมิติแบ่งกลุ่มอัตโนมัติ** — ถ้า "อายุ" มีค่าเดียว จะสลับไปใช้ "เพศ" แล้วจึง "ได้พบข่าวยังไง" (`groupFallback` ในไฟล์หน้า)
- **ถ้าไม่มีมิติไหนแบ่งได้เลย** จะซ่อนกราฟแบ่งกลุ่มทิ้ง พร้อมบอกเหตุผล แทนที่จะโชว์กราฟแถวเดียว
- **เกณฑ์กลุ่มตัวอย่าง** ตั้งไว้ที่ 25 คน (`minSample` ใน `pages/analysis.js`) ต่ำกว่านี้จะขึ้นคำเตือนใต้คำตอบ
- **เกณฑ์ตัดสิน** ต่างกันต้องเกิน 10% ถึงจะสรุป (`threshold`) ไม่งั้นขึ้นว่า "ก้ำกึ่ง"

## รองรับข้อมูลที่จะเพิ่มเข้ามา
- **หลายแหล่งพร้อมกัน** — ใส่ `sources: [{id, label, sheetId, gid}, …]` ใน `config.js` ระบบจะดึงขนานกันแล้วรวมให้ พร้อมเพิ่มคอลัมน์ `__source` ไว้กรองว่ามาจากรอบไหน
- **แหล่งใดพังไม่ล้มทั้งระบบ** — ใช้ `Promise.allSettled` แหล่งที่โหลดไม่ได้จะขึ้นเป็นคำเตือน ส่วนที่เหลือยังแสดงผลปกติ
- **คอลัมน์ใหม่ไม่ต้องแก้โค้ด** — รวมคอลัมน์แบบ union ถ้าเพิ่มคำถามในแบบสอบถาม จะโผล่ในหน้า "ข้อมูลดิบ" ทันที
- **แคชในเครื่อง** — เปิดครั้งถัดไปเห็นข้อมูลเดิมทันทีระหว่างรอโหลดใหม่ (ตั้งอายุที่ `cacheMinutes`)
- **หัวคอลัมน์ซ้ำ** ถูกเปลี่ยนชื่อเป็น `(2)` อัตโนมัติ ไม่ให้ข้อมูลทับกัน

## ลำดับความสำคัญ 3 ระดับ
ต่างกันที่ *ขนาด + เงา + สี + ระยะห่าง* ไม่ใช่แค่ตัวหนา
| ระดับ | หน้าตา | ใช้กับ |
|---|---|---|
| **L0** การ์ดคำตอบ | พื้นดำ เงาลึกสุด ตัวเลข 60px | คำตอบของคำถามวิจัย |
| **L1** `level: 1` | การ์ดขาว เงาลึก หัวข้อ 27px | กราฟหลักของหน้า |
| **L2** `level: 2` (ค่าเริ่มต้น) | การ์ดขาว เงากลาง | กราฟทั่วไป |
| **L3** `level: 3` | พื้นเทาอ่อน ไม่มีเงา มีเส้นขอบ ตัวเล็กลง | ข้อมูลประกอบ |

ในแต่ละกราฟ **แถวอันดับ 1 เด่นกว่าเพื่อน** (พื้นอ่อน ๆ ตัวหนา หลอดหนากว่า ป้ายตัวเลขเป็นสีทึบ)

## จังหวะอนิเมชัน (วัดจากหน้าเว็บจริง)
| ส่วน | เวลา |

| ดึงข้อมูลจาก Google Sheet | **~440 ms** ← ตัวหลักที่ทำให้รอ |
| สลับหน้า (JS) | 1–2 ms |

| แถวอันดับไล่ขึ้น | 320 ms + หน่วงสูงสุด 168 ms |
| ตัวเลขวิ่งขึ้น | 600 ms |

รองรับ `prefers-reduced-motion` — ผู้ใช้ที่ตั้งค่าลดการเคลื่อนไหวจะเห็นผลลัพธ์ทันทีไม่มีอนิเมชัน

## รูปแบบการแสดงค่า (เลือกให้เหมาะกับข้อมูล)
| `type` | หน้าตา | เหมาะกับ |
|---|---|---|
| `gap` | สองฝั่งซ้าย-ขวา + ส่วนต่างตรงกลาง | เทียบสองฝั่งเป็นหลัก |
| `compare` | ช่องว่างของแต่ละกลุ่ม + ผลทดสอบ | ตอบว่า "พฤติกรรมไหนสัมพันธ์กับช่องว่าง" |
| `paired` | ชื่อ + แท่งสองแท่ง + ป้ายบอกว่าฝั่งไหนนำ | **เทียบรายการเดียวกันสองฝั่ง** — แทนกราฟแท่งสองใบ |
| `chips` | ป้ายขนาด/สีตามจำนวน | รายการยาวที่ไม่ต้องเทียบละเอียด |
| `rank` | อันดับ + หลอด | จัดอันดับที่ต้องอ่านค่าแม่น |
| `waffle` | 100 จุด = 100% | สัดส่วนที่อยากให้ "นับได้ด้วยตา" |
| `heatmap` | ตาราง 2 มิติไล่เฉด | หัวข้อ × กลุ่ม |
| `bubbles` | วงกลมขนาดตามค่า | หมวดไม่กี่อันที่อยากเห็นความต่างของขนาด |
| `stacked` / `donut` | สัดส่วนรวม 100% | คำตอบแบบเลือกข้อเดียว |
| `gauge` | เข็มครึ่งวงกลม | ค่าเดียวเทียบกับสเกล (ปัจจุบันไม่ได้ใช้ในหน้าหลัก) |

**หลักที่ยึด:** ถ้าหน้าไหนมีกราฟแท่งซ้ำกันเกิน 2 ใบ ให้เปลี่ยนเป็น `dumbbell` (ถ้าเทียบกันได้) หรือ `chips` (ถ้าแค่ดูว่าอะไรเยอะ)
ตัวอย่าง: หน้า "เหตุผลเบื้องหลัง" เคยมีกราฟแท่ง 4 ใบ ตอนนี้เหลือ `paired` 2 ใบที่เทียบให้ในตัว

> เคยลองแบบ dumbbell (จุดสองจุดบนเส้น) แล้วอ่านยาก เพราะไม่มีแกนให้อ้างอิงตำแหน่งจุด
> และตัวเลข "11 / 17" ต้องเดาว่าเลขไหนคือสีไหน จึงเปลี่ยนมาเป็นแท่งที่มีชื่อกำกับทุกแท่ง

## หลอดวัดค่า
หลอดเป็นข้อมูลประกอบ ไม่ใช่พระเอก จึงบางลง (6px · อันดับ 1 = 8px) และจำกัดความยาวสูงสุด 340px เพื่อให้เหลือช่องว่างด้านขวา
สีทึบสีเดียว ไม่ไล่เฉด · ตัวเลขเป็นข้อความล้วน ไม่ทำเป็นป้ายวงกลม เพราะชนกับเลขลำดับด้านซ้าย

**แถบสรุปด้านบน** ลดความสูงลงราวครึ่งหนึ่ง (ตัวเลข 42px → 27px, padding 15px → 10px)
รายละเอียดรอง (จำนวนคน + ช่วงความเชื่อมั่น) ย้ายไปอยู่ใน tooltip แทนการกินพื้นที่แนวตั้ง

**อันดับ 1** ทำเป็นแถบเด่นแยกจากรายการ: **กรอบบาง 1.5px รอบใบ** + พื้นอ่อน ๆ + ป้าย "อันดับ 1" + ตัวอักษร 27px + ตัวเลข 42px + หลอดหนา 14px (แถวอื่น 8px)
สีกรอบและพื้นผสมมาจาก `--accent` ของการ์ดใบนั้นด้วย `color-mix()` — การ์ดข่าวโลก (ดำ) ได้กรอบเทา การ์ดข่าวดราม่า (ม่วง) ได้กรอบม่วง ไม่ต้องตั้งค่าเพิ่ม

**hover ของแถวข้อมูลทุกชนิด ประกาศไว้ที่เดียว** ท้ายไฟล์ `4-components.css`
```css
.rank-row, .bigbar, .sg-row, .dl-row, .wf-item, .stack-item { ...ค่าเริ่มต้น... }
.rank-row:hover, .bigbar:hover, ... { พื้น --hair + ยกขึ้น 1px + เงานุ่ม }
```
เพิ่มแถวชนิดใหม่ ให้เอา selector มาต่อในลิสต์นี้ — ห้ามเขียน `:hover` แยกรายคอมโพเนนต์ เพราะเคยทำแล้วค่าเพี้ยนกันคนละหน้า
ทุก state ประกาศค่าเริ่มต้นไว้ล่วงหน้า transition จึงลื่นทั้งตอนเข้าและตอนออก (.28s ease)
ระยะระหว่างแถว: padding 14px และตัดเส้นคั่นออก ให้ช่องไฟทำหน้าที่แบ่งแทน

## ออปชันกราฟ## ออปชันกราฟที่ใช้ได้
- `type: "diverge"` — เทียบสองฝั่งรอบแกนกลาง ใช้กับ `ys: [ชุด A, ชุด B]`
- `type: "rank"` — อันดับพร้อมแถบ (`color`, `trackColor`, `showPercent`)
- `type` bar/line/pie/doughnut — กราฟ Chart.js ปกติ
- ใช้ร่วมกันได้: `agg` count/sum/avg · `multi:true` แยกคำตอบหลายข้อ · `sort` value/label · `top:N` · `wide:true` เต็มความกว้าง · `note` คำอธิบายใต้หัวข้อ
- หัวเรื่องใส่ `[...]` ครอบคำไหน คำนั้นจะเป็นสีเน้น

## ออปชัน KPI card
- `spark: { x, y, agg, shape: "bars"|"area", color }` — กราฟจิ๋วในการ์ด (SVG เขียนเอง ไม่ใช้ไลบรารี)
- `foot: { label, column, agg, unit, compare }` — บรรทัดล่างใต้เส้นคั่น ใส่ `compare` เพื่อโชว์ลูกศร ▲▼ เทียบกับอีกคอลัมน์
- `tone: "accent" | "world"` — สีตัวเลข

## แท็บ
`tabs: [{ label }, { label, column, value }]` — แท็บแรกไม่ต้องใส่ column = ดูทั้งหมด

## ออปชัน KPI
`agg` sum/avg/count/distinct/max/min/last และ `share` + `equals` (= % ของผู้ตอบที่คำตอบมีคำนั้น)

index.html          โครงหน้าเว็บ
config.js           ← แก้ไฟล์นี้ไฟล์เดียว (แหล่งข้อมูล, KPI, กราฟ, ตัวกรอง)
assets/css/style.css  ธีมขาว เรียบง่าย + พาเลตต์สีข้อมูล

## 1. เชื่อม Google Sheet
เปิดชีต → File → Share → **Publish to web** → เลือกชีต + **Comma-separated values (.csv)** → Publish
คัดลอก URL มาใส่ `csvUrl` ใน `config.js`

หรือใช้ `sheetId` + `sheetName` (ชีตต้องตั้งเป็น "Anyone with the link – Viewer")

## 2. ตั้งค่า KPI / กราฟ
ใน `config.js` — `column` คือ **ชื่อหัวคอลัมน์แถวแรกของชีต** (ต้องตรงตัวอักษร)
- `kpis`: `agg` = `sum` `avg` `count` `max` `min` `last`
- `charts`: `type` = `bar` `line` `pie` `doughnut`
- `filters`: dropdown จากค่าไม่ซ้ำในคอลัมน์

## ขึ้น GitHub Pages

```bash
cd ~/Downloads/Dashboard
git init
git add .
git commit -m "News behavior dashboard"
git branch -M main
git remote add origin https://github.com/<ชื่อผู้ใช้>/<ชื่อ repo>.git
git push -u origin main
```
จากนั้นในหน้า repo → **Settings → Pages → Source: Deploy from a branch → main / (root)**
รอสักครู่จะได้ URL `https://<ชื่อผู้ใช้>.github.io/<ชื่อ repo>/`

**ก่อน push ควรตัดสินใจ 2 เรื่อง**
1. **โฟลเดอร์ `fonts/` (ไฟล์ .ttf ต้นฉบับ 17 ไฟล์ ~2 MB)** ไม่จำเป็นต้องขึ้นเว็บ เพราะเว็บใช้ `.woff2` ใน `assets/fonts/` แล้ว
   ถ้าไม่อยากเผยแพร่ไฟล์ฟอนต์ต้นฉบับ ให้เพิ่ม `fonts/` ใน `.gitignore`
2. **โฟลเดอร์ `เอกสาร/` (PDF งานวิจัย ~32 MB)** เป็นเอกสารลิขสิทธิ์ของผู้อื่น **ไม่ควร push ขึ้น public repo**
   ระบบไม่ได้อ่านไฟล์เหล่านี้ตอนรัน (ตัวเลขถูกคัดมาไว้ใน `core/benchmarks.js` แล้ว) — เพิ่ม `เอกสาร/` ใน `.gitignore`

> **DB Heavent เป็นฟอนต์ลิขสิทธิ์** สิทธิ์ใช้งานบนเว็บ (webfont) มักแยกจากสิทธิ์ใช้บนเครื่อง
> ถ้าเว็บนี้จะเผยแพร่สาธารณะ ควรตรวจสอบสิทธิ์กับผู้จำหน่ายก่อน
